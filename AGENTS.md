# Repository Guidelines

## Shared Harness Instructions

Read `~/.agents/harness/instructions.md` (symlinked as `~/.agents/AGENTS.md`)
alongside this file. It carries the operating discipline, token, and safety
rules intended for every agent harness, though some adapters do not load it
yet -- `just harness-audit` tracks which. It is generated from
`scripts/agent-harnesses.py`; edit the generator, never the output.

## Tessl Plugin Rules

Read `~/.tessl/RULES.md` when a task involves tessl skills or plugins. It is
generated by `tessl install` from `~/.tessl/tessl.json`; those two files are
tracked, and every other path under `~/.tessl/` is ignored runtime state or
credentials. `tessl init` re-injects `@../.tessl/RULES.md` pointers into
`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.gemini/AGENTS.md`, and
`~/.copilot/copilot-instructions.md` -- delete them. This section is the only
inclusion point, and `tests/tessl-inclusion.bats` fails if they come back.

## Project Overview

This repository is a macOS **workstation configuration** repo: personal dotfiles
plus the automation that keeps them consistent. It is not an application -- there
is no single binary or server. The git checkout at `~/dev/dotfiles` is deployed
into `$HOME` as symlinks by `mise dot`, so the repo *is* the home directory
configuration. It hosts four independent source domains:

| Domain | Language | Root |
| --- | --- | --- |
| Interactive shell library (primary) | Nushell | `.config/nushell/autoload/` |
| Interactive shell library (fallback) | zsh/bash | `.config/zsh/functions/` |
| Safety guard binary | Rust | `crates/ness/` |
| Repo/harness tooling | Python 3 | `scripts/` |
| Harness runtime adapters | TypeScript | `.omp/agent/`, `.pi/agent/`, `.config/opencode/plugins/`, `.opencode/plugins/` |

Repo-only paths (`docs/`, `tests/`, `crates/`, `.github/`, `justfile`, `hk.pkl`,
`pyproject.toml`) never land in `$HOME`.

## Architecture & Data Flow

**Deployment.** `git ls-files` -> `scripts/home_spec.py` -> `.config/mise/conf.d/dotfiles.toml`
(2300+ symlink entries) -> `mise dot apply` -> `$HOME`. The git hook
`scripts/home-apply-hook` re-applies after checkout/merge/commit/rewrite;
`scripts/home-capture.py` copies app-rewritten files back into the repo.

**Harness generation (the central pipeline).** Hand-written sources in
`.agents/harness/`, `.agents/skills/`, and `.codex/agents` are rendered by
`scripts/agent-harnesses.py generate` into every native harness directory
(`.claude/`, `.codex/`, `.config/opencode/`, `.pi/`, `.omp/`, `.grok/`,
`.config/crush/`, `.cursor/`, `.gemini/antigravity-cli/`). The output map is
`.agents/harness/generated-paths.json`. ~340 tracked files carry the
header `<!-- Generated by scripts/agent-harnesses.py; do not edit directly. -->`
-- **edit the generator, never the generated output**.

**Safety guard (the critical runtime path).**

```
harness tool call
  -> PreToolUse hook (bash shim / TypeScript plugin)
    -> ~/.local/bin/ness hook --harness <slug> --tool <tool>
      -> hook.rs           (harness-specific payload/response shape)
        -> guard_eval.rs   (policy, then generated-artifact override)
          -> active.rs     (~/.config/ness/policy.toml + ~/.local/state/ness/applied.json)
          -> policy.rs     (fancy-regex match tables)
            -> shell.rs    (brush-parser bash AST -> "prompt" verdict)
          -> manifest.rs   (.agents/harness/generated-paths.json)
```

Policy authoring is a separate, human-gated flow: an agent writes a candidate
under `~/.local/state/ness/proposals/`, `ness policy check <candidate>` reports
schema errors, invariants, verdict diffs and case deltas, and only a human at a
TTY can run `ness policy apply` (the apply command is itself in
`[commands.dangerous]`, so an agent is denied it).

**Policy as data.** `.config/ness/policy.toml` (1300+ lines) holds the entire
safety policy: protected paths, secret content, command classes, write targets,
approval modes, and shell classification tables. `.config/ness/cases/` holds 220
JSON guard cases that are the executable spec.

## Runtime / Tooling Preferences

- **mise is the primary version manager**; every runtime pin lives in
  `.config/mise/config.toml` `[tools]` (`python 3.15.2`, `node 26.13.0`,
  `bun 1.4.4`, `rust 1.99.1`, `go 1.27.3`, `java 27.0.1+0`, ...). There is no
  `mise.lock` by decision (`minimum_release_age = "24h"`), and no
  `.tool-versions`/`.nvmrc`/`rust-toolchain.toml`.
- Homebrew (`Brewfile`) is the fallback; Nix/home-manager is an intentional,
  unsynced experiment.
- **Python 3.11+** is required for `tomllib`. `scripts/agent-harnesses.py`
  imports `tomllib` lazily on purpose (launchd/system-Python-3.9 contexts) --
  keep heavy imports out of import time and keep `provenance` on the fast path.
- Rust toolchain via `rustup` (stable + `llvm-tools`), `sccache` as
  `rustc-wrapper` (`.cargo/config.toml`). `crates/ness/Cargo.lock` is the only
  real dependency lockfile.
- TypeScript in `.omp/` runs on **bun**; `.config/opencode/` uses npm.
  `hk` cross-checks the `hk.pkl` Pkl pin against the mise pin
  (`scripts/check-hk-version.sh`) -- keep both at 2.11.0.
- `shfmt` is unpinned from 3.13 and tracks 3.14.x (`.config/mise/config.toml`).
- Deploy spec is derived from `git ls-files`: adding a tracked file requires
  `just home-spec` (or `just generate`), else `just home-spec-check` fails.
- `mise dot apply` does not prune removed links; `just home-status` reports drift.

## Development Commands

Run from the repo root; `just --list` shows the flat grouped index.

- `just deps` (alias `i`) -- install pinned tooling via mise, brew, bun, rust, git filters/hooks.
- `just format` -- format everything (`hk fix --all`).
- `just lint` -- full lint/format check (`hk check --all`).
- `just typecheck-python` -- basedpyright over `scripts/`.
- `just generate` -- regenerate harness artifacts, OMP profiles, and the home spec.
- `just harness-generate` / `just harness-validate` / `just harness-audit` -- generator parity.
- `just home-apply` / `just home-status` / `just home-capture` / `just home-deploy <ref>` -- deploy to `$HOME`.
- `just test` -- full Bats suite in parallel (needs `rush`); `just test abort` -- serial, fail fast.
- `bats tests/<name>.bats` -- run only the Bats file relevant to the change.
- `just ness-test` -- `cargo test --locked` for the Rust guard.
- `just check` -- the aggregate gate: lint, typecheck, spelling, harness check, agentlink check, home-spec check, ness-test, test.
- `just doctor` -- local environment diagnostics.

## Code Conventions & Common Patterns

**Language-specific**

- *Rust (`crates/ness/`)*
  - `//!` module doc at the top of every file, usually naming the Python original it ports; ported functions cite `file.py:line-range`.
  - Errors are `Result<T, String>` with a user-facing reason; no custom error enum.
  - **Fail closed everywhere**: a policy that fails to load denies; a regex runtime error denies. The single deliberate fail-open is `manifest.rs` (a stale generated-paths manifest must not wedge every write).
  - No global mutable state; `Compiled` is passed explicitly down the call chain. Configuration is injected by path, never by env var -- an override seam would be agent-reachable (the `ness` binary path is a hardcoded `~/.local/bin/ness` for the same reason).
  - Unit tests live in `#[cfg(test)] mod tests` per module; integration tests in `crates/ness/tests/`.
- *Python (`scripts/`)*
  - `snake_case` functions, `#!/usr/bin/env python3`, stdlib-first.
  - Modules that are imported (not executed) live alongside scripts with mode 644 and must do **no I/O at import time**.
  - Errors: `raise` / `sys.exit(1)` with a printed reason; `check`/`audit` subcommands exit 1 with a report; generators exit non-zero on drift.
  - Heavy imports (`tomllib`, `subprocess`) stay inside functions or a guarded block.
  - Script names use hyphens for executables (`sort-tools.py`) and underscores for importable modules (`harness_paths.py`).
- *Nushell (`.config/nushell/autoload/`)*
  - One command per file; stem == command name; subcommands via `export def "ghrun retry"`.
  - Private helpers are `def` (unexported) with a command-prefixed kebab-case name (`ghrun-usage`).
  - `--flag: type = default` with an inline `# comment` that becomes the help text.
  - Errors: `error make {msg: ...}` (127 uses); `try { } catch { }` for optional probes; `do -i { }` to ignore errors.
  - No async; long runners poll with `loop { ... sleep }`. State is `$env.*` plus `mut` locals.
  - Autoload files must be load-time pure -- `scripts/check-nushell-autoload.py` fails on top-level executable statements (including top-level `let`/`mut`).
- *TypeScript (`.omp/`, `.pi/`, `.config/opencode/`)*
  - `camelCase` functions, `PascalCase` exported types (`GuardResult`, `Capability`).
  - `execFileSync`/`execFile` with explicit timeouts (5000 ms for the guard).
  - Fail closed: `catch { return {decision: "deny", reason: "Shared guard failed closed"} }`; ledger appends swallow all errors -- recording must never break a session.
  - Bun tests are colocated: `<source>.test.ts`.
- *Shell (`scripts/*.sh`, hook shims)*
  - `set -euo pipefail`; hook shims `trap ... ERR` and deny on any failure.
  - Guard shims infer their harness from `$0` so one script serves two directories.

**Cross-cutting**

- **Generated vs. hand-authored is a hard boundary.** Generated roots are staged
  by hk: `.agents/harness/**`, `docs/harness/**`, `docs/agent-harnesses.*`,
  `.omp/agent/**`, `.omp/profiles/**`, `.pi/agent/**`, `.grok/**`,
  `.config/crush/**`, `.config/opencode/**`, `.cursor/hooks.json`,
  `.config/mise/conf.d/dotfiles.toml`, `.claude/skills/**`.
- **Control plane vs. agent-editable** is encoded in the policy's
  `[control_plane]` table: `scripts/agent-harnesses.py` and
  `scripts/harness_policy.py` may not be edited by an agent.
- Naming: lowercase; hyphens for scripts/docs/slugs, `snake_case` for Rust and
  Python identifiers, `camelCase`/`PascalCase` for TypeScript.
- Docs: one H1, short intro paragraph, tables, relative links. Decision records
  `docs/decisions/YYYY-MM-DD-slug.md` (frozen once accepted; corrections only
  via `## Errata`). Backlog items `docs/backlog/<slug>.md` with exactly one
  `Priority:` line.
- Never hard-wrap prose in markdown or commit bodies; let the renderer wrap it.

### Formatting Policy

- Every file tracked in this repo follows its language's standard formatter
  (`just format`, `.editorconfig`). Formatting is the default, not a per-file
  judgment call.
- The only exception is a tool that breaks when its tracked config or source is
  formatted normally. Document each exception where it applies, as
  `.gitattributes` and `scripts/sort-codex-config.py` already do for Codex's
  marketplace key order and machine-managed state.
- Rationale: uniform formatting keeps `just lint` fast and makes a diff
  meaningful. A tracked file that lands unformatted -- or wholesale reformatted
  -- is evidence the change was not reviewed.
- Let the formatter own whitespace; never hand-churn it. Do not reformat lines a
  change does not touch. Agent writes (pi, OMP) that leave existing whitespace
  as found are fine -- behavior-neutral, and better than a drive-by reformat
  that buries the real diff.

## Testing & QA

- **Primary framework: bats-core** (`bats 1.14.0`). Tests live in
  `tests/<subject>.bats` with hyphenated subject names and descriptive test
  names (`@test "shellcheck is available" { ... }`). Shared helpers:
  `tests/helpers/setup.bash` (`load helpers/setup`), with `source_zsh_function()`,
  `run_zsh_function()`, `command_exists()`.
- **Command:** `just test` (parallel across files via `rush`,
  `--no-parallelize-within-files` -- never parallelize within a file; fixtures
  race) and `just test abort` (serial, fail fast). `HOME` is remapped to the
  checkout inside the recipe, and `commit.gpgsign=false` is exported; several
  tests skip explicitly when `HOME` is not the checkout.
- **Python tests** are `unittest` files at `tests/test_<module>.py`, mirroring
  the script under test (`test_backlog.py` -> `scripts/backlog.py`). They are
  *not* run by pytest -- they are invoked from bats (`tests/python-scripts.bats`,
  `tests/agent-harnesses.bats`, `tests/omp-profiles.bats`) and asserted on exit
  status. Each loads its target via `importlib.util.spec_from_file_location`.
- **Rust tests:** `just ness-test` -> `cargo test --locked --manifest-path
  crates/ness/Cargo.toml`. `crates/ness/tests/corpus.rs` is the deepest
  integration layer: it drives 220 JSON cases in `.config/ness/cases/` and 61
  hook payloads in `crates/ness/tests/hook_corpus/` through 8 real harness
  shims.
- **TypeScript:** `bun test ./cmux-attention.test.ts` from
  `.omp/agent/shared/` -- not wired into `just test` or CI.
- **Harbor eval:** `just harness-evals` for the harness-structure eval under
  `.agents/harness/evals/harbor/harness-structure/`.
- **No coverage tooling or thresholds** are configured; do not invent one.
- Run `just lint` and only the Bats files relevant to the changed behavior.
  Run the repository-wide suite only when the user explicitly requests it.
- **CI:** `.github/workflows/check.yml` (lint job on `arc-ubuntu-24.04-arm64`
  running `just lint typecheck-python`; test job on `macos-latest` running
  `just test`), `.github/workflows/agent-harness-parity.yml` (harness parity +
  `just ness-test`), `agentic-review.yml`, `human-approval.yml` (PRs labeled
  `agent-authored` need a `human-approved` label). `.github/scripts/changed.sh`
  decides per-workflow relevance by path regex and fails open.
- `.harness/` describes an older pipeline (lint, tests, Nix build) but is inert:
  it triggers on GitHub webhooks and the repo has none configured, so it cannot
  run. Do not treat it as a gate or spend time maintaining it.

## Agent Response Language

- Respond in the language used by the user's latest message.
- If the user's language is unclear, use English.
- Keep code, code comments, and command output unchanged unless translation is explicitly requested.

**Nested repositories:** Some subdirectories (especially `dev/`) are separate git repos. The working directory is already `~`; run git directly or use `git -C ~` (avoid a redundant `cd ~`), and confirm which repo you are in before committing.

## Web & Documentation Search (Exa)

Use `~/.claude/skills/exa-search/scripts/exa.sh` to verify API signatures, look
up library usage, or check a config format — including when you think you
already know the answer, since library APIs drift. `EXA_API_KEY` is read from
`~/.env`; never pass the key on a command line.

```bash
exa.sh context "expose a Rust struct to Node via napi-rs threadsafe function"
exa.sh search  "napi-rs breaking changes" --domains github.com --since 2026-01-25
```

`context` is the default — it returns one budget-capped string and is the
token-efficient path for anything code-shaped. Fall through to `search` only for
recency (`context` has no date filter), provenance control (`--domains` /
`--exclude`), or when `context` comes back empty. Narrate that fallback, and do
it at most once; if `search` is also thin, say so and stop rather than
escalating to `--type deep-reasoning`.

Defaults (`--type auto`, `--results 10`, highlights capped at 600 chars) are
right for nearly every coding question. Full parameter tables and API footguns
are in `~/.claude/skills/exa-search/references/search-tuning.md`.

## Documentation Convention

This repo follows [Conventional Docs](https://github.com/phatblat/conventional-docs)
(skill installed at `~/.agents/skills/conventional-docs`, symlinked from
`~/dev/agents/conventional-docs`).

- `docs/charter.md`'s Artifacts table is authoritative for where each
  document lives.
- Decision records are `docs/decisions/YYYY-MM-DD-slug.md`; a record is
  frozen once accepted or rejected and corrected only by appending to its
  `## Errata` section.
- `PLAN.md` and `TODO.md` at the repo root are branch-scoped: written per
  branch, committed for handoff, and deleted before merge.
- Queued work that is real but not being done now is filed as
  `docs/backlog/<slug>.md`, one file per item, and deleted by the change
  that implements it. Each item carries exactly one
  `Priority: Urgent|High|Medium|Low|Unprioritized` line under its H1;
  `just backlog new "<title>" [priority]` creates one, and `just backlog`
  (alias `just bl`) lists them grouped by priority.
- The repo keeps no `CHANGELOG.md` — it has no releases.

See `docs/decisions/2026-09-07-adopt-conventional-docs.md` for the adoption
decision and rationale.

## Commit & Pull Request Guidelines
- Use Conventional Commit prefixes seen in history (`feat:`, `fix:`, `chore:`, `deps:`, `style:`, `test:`, `ci:`), optionally scoped (`feat(justfile): ...`). Documentation events add `decision:`, `plan:`, and `todo:`: `decision: propose <id>` / `decision: accept <id>` / `decision: reject <id>`, `plan: start <id>` / `plan: done <id>`, `todo: sync` / `todo: clear`. Each of these subjects is the id in full, is exempt from the 50-char subject guidance below (still capped at 72), and its commit touches exactly one artifact (the decision file, `PLAN.md`, or `TODO.md`).
- Follow `.gitmessage`: imperative subject, capitalized, no trailing period, <= 50 chars; wrap body at 72 chars and explain what/why.
- PRs should include: concise summary, changed paths, commands run locally, and any relevant config/output screenshots.
